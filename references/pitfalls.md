# 踩坑手册（本 skill 的核心经验，全部实战验证过）

## 渲染器与格式

1. **用户的 Markdown 预览器禁用内联 HTML**。`<img width>`、`<p align>` 等标签会被过滤 → 图片直接消失。
   图片只能用 `![图注](路径)` 标准语法；显示尺寸无法在 md 里控制，靠缩小 PNG 固有尺寸（≤1400px）缓解。
2. **`$$` 公式块内部出现空行 = pandoc 解析失败**。docx 里会出现字面 `$$`、`U_2 =  =  $$` 之类的残段，公式内容丢失。
   规避：`$$` 块内部禁止空行；批量排版脚本处理完必须再扫一遍块内空行。
3. LaTeX 里**不要用 Unicode 下标字符**（₁₂₃ᵢ）。SimHei 等中文字体没有这些字形；docx 场景虽然用 OMML 不受影响，但 md 预览和图注会出豆腐块。一律用 `$_1$`、`$\mathrm{in}$`。
4. 中文串与公式混排时，把整个表达式（含单位）放进 `$...$`，用 `\mathrm{V}`、`\,\Omega`；散文里的"＝"（表示"就是"）保留纯文本。

## PDF 渲染与裁图

5. **pdftoppm/pdftocairo 不认 Git Bash 的 `/c/...` 路径**，必须传 `C:/...` 风格，否则报 `Could not write image`，容易被误判成字体问题。
6. `/tmp` 在 Git Bash 里实际是 `C:/Users/<user>/AppData/Local/Temp`——用 `Read` 工具查看渲染结果时要换算。
7. pdftoppm 300dpi：幻灯片约 4000×2250px，Skript A4 约 2480×3508px。裁剪坐标一律用**页面宽高的分数**表达，与 DPI 无关。
8. **幻灯片里图形与文字/其他图常常横向紧邻**，纯矩形裁剪必然互相污染。手段：
   - **行带分析**：按行统计暗像素（`min(R,G,B)<235` 计非白），得内容行带 → 精确定 y 边界（防正文残行、防切 x 轴刻度和轴标签）；
   - **颜色检测**：浅蓝信息框用 `(B-R>12)&(B>160)` 掩码 + 连通域标记（BFS），拿到框的精确边界 → 框内内容完整、框外文字不混入；
   - **局部涂白**：裁剪矩形与图形区必然重叠时（如公式块右侧紧贴曲线图），裁后把重叠角涂白——先确认该区域确实没有要保留的内容（用行带聚类验证每个内容元素的 x 范围）。
9. **每张图裁完必须用 ViewImage 目检**（`Read` 只返回路径，看不了图）：完整、无杂物、标签没被切。目检时重点看四角和边缘；**同路径有缓存，核验前复制成新文件名**。
10. **禁止手绘电路图替代原图**（matplotlib 画的再好也不如老师原图可信，用户明确否决过）。
11. 裁图坐标写进 spec.json 存档，重建/换 DPI 时一键复现。
12. compose 拼图时，若某个子框左侧紧邻文字列，把该框左边界右移（pad_left），不要依赖 autotrim。

## md → docx

13. 用 **pypandoc-binary**（自带 pandoc 3.9，`pip install pypandoc-binary`）。整篇笔记的公式块与公式对象转换实测无损，OMML 原生可编辑。不要走其他 docx 生成管线（不保真公式）。
14. 图片宽度在**构建副本**里用 pandoc 属性 `{width=Xcm}` 控制（宽幅 15cm / 中等 10–13cm / 竖图 6–8cm），**不要改源 md**——源 md 必须保持纯 Markdown。
15. pandoc 转完必须 python-docx 后处理：中文字体（正文宋体/标题微软雅黑，否则中文回退难看）、图片段落居中、表头加粗、图注 9pt、页脚 PAGE/NUMPAGES 域、页边距。
16. docx 校验三件套：`<m:oMathPara>` 数 == md 的 `$$` 块数；`word/media/` 图片数 == md 引用数；全文不得有字面 `$$`。
17. docx 有问题**永远回查 md 重建**，不要手改 docx（下次重建就丢了）。
18. pandoc 的 docx 目录是 TOC 域，打开后需右键"更新域"才有页码——交付时要提醒用户。
19. 表格在 docx 里用 pandoc 默认样式（无表头加粗），必须后处理补：首行 bold + 表内 9.5pt。
20. Windows 常见安装：MikTeX 自带 poppler（在安装目录的 `bin\x64` 下）；LaTeX 发行版（如 TeXLive）也可能提供 PDF 工具链。

## 行内公式与 Word 可读性（v2 关键升级）

21. **pandoc 把所有行内 `$...$` 转成 OMML 公式对象**——一篇笔记 400+ 个小公式对象塞在正文里，Word 阅读体验极差（中文德文排布被打乱、字号突兀、行距破碎），这是"Word 版不能用来预习"的主因。
22. **解法：行内公式轻量化**——构建后遍历 `m:oMath`，把"纯文本+上下标"的简单行内公式（`R_M`、`U_0`、`G_a(φ_a-φ_b)` 等）降级为**普通文本运行 + `w:vertAlign` 真下标/上标**；独立公式（`m:oMathPara` 内）与含分数/矩阵/根号的复杂结构保持 OMML。实测一篇笔记里大部分行内公式可降级。
23. 判定规则：oMath 子元素只允许 `m:r`/`m:sSub`/`m:sSup`（跳过 `*Pr`），总文本 ≤48 字符、部件 ≤14 个；基底/上下标内再嵌套结构则放弃转换。
24. **天坑**：生成普通文本运行时，`vertAlign` 只能在 sub/sup 为真时写入——无脑 `set("superscript")` 会把所有普通字符抬高（已踩过，靠抽查段落 XML run 属性发现）。
25. 配套可读性措施：表格加边框+表头底纹、正文 11pt/列表 10.5pt、行距 1.3、Block Text 引用块灰化缩进、标题配色分层。
26. 校验手段：抽查典型段落的 run 序列（文本 + vertAlign 属性逐个打印），比只看统计数可靠。

## 裁图与排图（第二章实战补充）

27. **Skript 的插图常常左右双栏并排**（如"1. Reihenschaltung | 2. Parallelschaltung"），按左栏估坐标会只裁到一半——先裁全宽再用行带确认，或看缩略拼图确认布局。
28. **图内自带的编号/标签（a)、b)、1./2.、"3. Zwischenschritt…"）必须保留**，被切的半截正文文字宁可裁掉也不要留在图边（用户对"图片信息不全+文字残片"都敏感）。
29. 连续多图堆叠是可读性大敌：相邻图之间必须有锚点文字（这张图看什么、对应哪一步）；能合并的相关子图裁成一张。
30. 幻灯片/讲义页上图形与正文横向紧邻是常态，裁图边界宁可用"行带聚类测出每个内容元素的 x 范围"来定，不要估。

31. **目录锚点链接必须脚本生成，禁止手写 slug**。标题是"中文 + 德语 + 全角括号"混合体，手算 slug 必错（漏掉全角括号剔除规则、ü/ß/§ 的处理等）。用 `md_to_docx.py --fix-toc` 从实际标题自动生成（github-slugger 规则：小写、剔除非字母/数字/空格/连字符、空格→连字符、保留 CJK 与变音字母），自检器校验每个锚点与标题匹配；标题改动后必须重跑 --fix-toc。
32. 改标题（如"2.1 滤波器"→"2.1 滤波器（Filter）"）时记得同步目录条目文字——目录与标题名不一致也会被用户当作"锚点坏了"。


## 改稿残骸与自检盲区（第五章实战补充）

33. **`Read` 看不了图，目检必须用 ViewImage**；而且**同一路径的图 ViewImage 会返回缓存旧图**——涂白/重裁后"看起来没变"多半是缓存。核验前先 `cp` 成新文件名（`foo_v2.png`）再看，别怀疑自己的处理逻辑。
34. **表格与公式混排的三个坑**（第五章一次踩全）：
    - `$$` 块里塞了 Markdown 表格行（`|  |  |` / `| --- | --- |`）→ pandoc 把表格当公式内容，整块公式坏掉；
    - **表头全空的残表** → 多半是把"三行对照表"改写成列表时留下的空壳，渲染成一个小白框；
    - **`$|\underline{S}|$` 被表格竖线切成三格** → `$` 失配、公式断成两截。表格里的模一律写 `\lvert S \rvert`。
    这三种 `--check-only` 现在都会报（v3 起），但改完仍要人眼看一遍表格区。
35. **幻灯片正文压在图例上方**：spec 里加 `wipe` 框，按 `keep` 颜色保留图例、其余涂白。若页面文字与曲线同色（蓝色链接 / 蓝曲线），颜色法分不开——只能把 wipe 框收在图例上方，或直接下移裁剪边界（实测有一页 Folie 就这么处理）。
36. **"自检通过"≠"文档没问题"**。`--check-only` 只验结构（定界符、空行、表格、锚点、图片存在），不验 LaTeX 语法、不验内容。公式一律再过一遍 `katex_check.js`；实测数百个式子 0 失败，说明 `\lvert`、`\underbrace`、`\text{中文}` 都没问题。
37. **标题层级体检**：全文 0 个 `###` 是危险信号——长节会退化成连续段落，读者失去分步提示。长章 10–20 个是正常量级；但别每段一个（堆砌）。
38. **偏好扫描**：正文出现「考点：」、出现"德语"字样、清单用 `- [ ]`、德文术语未配中文，这几类都算踩项目约定，交付前扫一遍（第 7 项检查已内置前两条）。
39. **`###` 标题里尽量别写行内公式**：`--depth 3` 生成目录时会把 `$...$` 原文带进条目，锚点也变成 `#看图varphi--50circ-…` 这种怪东西。标题里的符号写成文字（"相位差 50° 时平均线落在哪"），公式留给正文。
40. **正文（非表格）行里出现裸竖线 `|`，整行会被渲染成一格格的"伪表格"**：外侧那格套着正文，中间几格只剩 `\underline{Z}` 之类的碎片，公式也不渲染。典型来源就是绝对值写法 `$Z = |\underline{Z}|$`、`$|\bar{u}|$`、`$r = |z|$`，以及图片 alt / 标题里的 `|ū|`。
    - 公式里的模一律写 `\lvert … \rvert`（KaTeX 与 docx 都正常）；求值竖线写 `\right\rvert`；矩阵里的列分隔写 `\vert`。
    - 标题、图片 alt 这类**不能放 LaTeX 的地方**，把 `|ū|` 改写成文字（"取绝对值的平均""整流平均值"），改完必须重跑 `--fix-toc`（标题文字变了，锚点跟着变）。
    - 表格单元格里的 `$|S|$` 是另一个坑（见 34），两处都用 `\lvert` 一并解决。
    - `--check-only` 自 v3.1 起对"非表格行含竖线"报错误；`$$` 块内部不查（块内是公式，安全）。

## 更新模式与工序（v4 补充）

41. **`--fix-toc` 的参数顺序不能反**：正确写法是 `md_to_docx.py 笔记.md --fix-toc --depth 3`。
    把 `--depth 3` 写在文件名前面，脚本会把 `"3"` 当成路径，报 `FileNotFoundError: '3'`。
42. **改过 `###` 标题后必须重跑 `--fix-toc`**，否则 `--check-only` 的锚点校验会报一串 `#slug 与任何标题的 slug 不匹配`。
    生成后建议把 `###` 条目缩进两格（`  - [...]`），几十条平铺的目录读起来像一堵墙，缩进后才是树。
43. **"老师更新了 PPT，补进笔记"之前，先确认文件真的换了**：`md5sum 旧.pdf 新.pdf`。
    浏览器下载重名会自动加 `(1)`，但内容可能是缓存的旧文件——本次实测两个文件 MD5 完全相同、逐页 diff 为 0。
    MD5 一致就别动笔记；不一致再逐页 `pdftotext` 比对（`split('\f')` 按页切，逐页 `re.sub(r'\s+',' ')` 后比较），
    先确认**页数是否变化**——页数一变，全文所有 `Folie N` 都要重新编号。
44. **发现"同一件事讲了两遍"时，先加交叉引用，不要急着删**：本次同一主题在"公式推导视角"与横向总结节（读图操作视角）各讲一次，
    两者的教学功能不同。做法是各加一句"来历见推导小节" / "怎么在陌生图上量出它见〈读图操作〉小节第 N 步"，比删掉一半安全。
45. **`preflight.py` 是工序凭据，不是文档检查器**：它把规则清单、条款级红线（`--check-only` 的盲区）、文风负面词、当前文件体检一次打出来。
    开工前跑、把输出留在对话里，用户据此判断"这一轮到底有没有走流程"。真正的门禁仍然是 `--check-only` + `katex_check.js`。

46. **`--check-only` 必须在笔记所在目录里跑**。脚本把 `![...](assets/x.png)` 当**相对当前工作目录**的路径去 `os.path.exists`，
    从仓库根跑会一口气报「图片不存在：assets/…」二三十条，看起来像图全丢了，其实一张没少。
    - 正确用法：`cd 笔记所在目录 && python md_to_docx.py 笔记.md --check-only`
    - 根治办法（待办）：把路径解析改成相对 **md 文件所在目录**，并加一条回归（从项目根跑也必须 0 错）。
47. **手工给目录加缩进，会让 `--fix-toc` 认不出来**。脚本只替换以 `- [` 开头的行；你把三级条目缩进成 `  - [`，
    它就当作不存在，于是**再追加一份新目录**——实测目录重复成两份、锚点全错。
    要么保持扁平（推荐），要么缩进后就别再跑 `--fix-toc`，改标题时手工同步。

## 行文约束（v4 补）

48. **术语首次出现要带一句人话括注，但基础词可豁免**。写 `**Wirkleistung 有功功率**（真正变成热、光、转动的那部分）`；
    而 电阻／电容／电感／阻抗／电压 这类中学就有的词不必加括注，否则每段都是括号，反而难读。
49. **源材料打架时以 PPT 为准**：Folien 与 Skript 的编排、例题数值不一致时，正文跟随 Folien，并在需要处注明"按 Folien 的编排"。
    方法学内容（解题步骤、取号规则）**禁止自编**，只能来自 PPT 或用户口述。
50. **多章共用一个 `assets/` 时，文件名必须带章节前缀**（如 `figure_6_1.png`）。检查器靠前缀区分"本篇该引用哪些图"，
    没有前缀时反向检查会把别章的图全算成本章漏引（实测一次大面积误报）。
51. **`Ortskurve`（轨迹图）这类只在 Skript 出现、PPT 没有的内容**：可以写，但要在小标题里标出来源与页号，
    不要混进按 PPT 顺序的正文里冒充同一套编排。
52. **建"页码→主题"索引必须逐页取**：`pdftotext -f 4 -l 50 x.pdf out.txt` 之后用 `out.txt.split('\f')[p-1]` 索引，
    得到的不是第 p 页——数组第一项是第 4 页，于是整体偏 3 页。本次就因此把整章所有小节的页码全标错一轮。
    正确做法：`for p in $(seq 4 50); do pdftotext -f $p -l $p ... ; done`，一页一次，宁可慢。
53. **PPT 上"看起来没图"的页，去 Skript 找**：第 60–63 页那种纯文字页（谐振回路从哪来、用在哪），
    PPT 确实只有 bullet；但 Skript 第 87 页有 LC 回路图和"弹簧振子 ↔ LC 回路"五行对照图，补进去正好填上缺口。
    判据：先在 PPT 渲染页目检确认无图，再翻 Skript 对应章节，别直接写"课件没有图"。
